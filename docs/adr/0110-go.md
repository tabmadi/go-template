# ADR-0110: Go

- **Status:** Accepted
- **Decides:** golangci-lint with every linter lints and formats the Go code, and Nix builds the static binary on a Go line that `go.mod` and `flake.nix` share.

## Context

The shared toolchain of [ADR-0100](0100-toolchain.md) holds no language. This ADR adds the tools of Go: the linter, the formatter, the Go line, and the build of the binary.

## Decision drivers

1. **Strict.** The linter finds every class of defect that a published linter finds, and each exception has a name and a reason.
2. **One tool.** One tool lints and formats, with one config in `.config/`.
3. **Pinned.** The tool and the Go line come from `nixpkgs` through the lock.
4. **Tested build.** Building the artifact also runs the tests.

## Considered options

### The linter and the formatter

| Option | 1 Strict | 2 One tool | Verdict |
| --- | --- | --- | --- |
| `go vet` and `gofmt` | The checks of the Go team only | Two tools | Rejected on driver 1 |
| staticcheck alone | Deep, but one linter of many | No formatter | Rejected on drivers 1 and 2 |
| revive alone | Style rules only | No formatter | Rejected on driver 1 |
| **golangci-lint with every linter enabled** | **Yes. It runs staticcheck, `go vet`, and more than a hundred other linters** | **Yes. Its `fmt` runs gofumpt, goimports, gci, and golines** | **Chosen** |

Sources:

- [golangci-lint linters](https://golangci-lint.run/usage/linters/), [golangci-lint formatters](https://golangci-lint.run/usage/formatters/), [staticcheck](https://staticcheck.dev/).

### The build of the binary

| Option | 3 Pinned | 4 Tested build | Verdict |
| --- | --- | --- | --- |
| `go build` in a recipe only | The Go of the dev shell | No | Rejected as the artifact. `just build` stays for a local binary |
| GoReleaser | A second tool and config | No | Rejected. The repo publishes no release archive |
| **`buildGoModule` in `flake.nix`** | **Yes** | **Yes. It runs `go test` on every package** | **Chosen** |

Sources:

- [buildGoModule in the nixpkgs manual](https://nixos.org/manual/nixpkgs/stable/#sec-language-go).

## Decision

golangci-lint is both the linter and the formatter. `.config/golangci.yml` enables every linter and disables each exception by name with a reason. The formatters are `gofumpt`, `goimports`, `gci`, and `golines` at 120 columns. Every recipe, check, hook, and Zed setting passes `--config .config/golangci.yml`.

| File type | Formatter |
| --- | --- |
| Go | golangci-lint, with tabs, per `gofmt` |

The Go line is 1.27: `flake.nix` takes `go_1_27` and `buildGo127Module`, and `go.mod` names the same line. A newer Go line waits until `nixpkgs` builds `golangci-lint` with it.

This repo adopts the `go` module of tabnix. It ships the ruleguard rules, which forbid an assignment in an `if` init statement and a comparison of errors with `==`, `!=`, or `switch`. `.config/golangci.yml` names them with `@tabnix-go-rules@`, and `internal/tools` keeps their DSL in `go.mod`.

The package in `flake.nix` is the artifact: a static, stripped binary at `result/bin/app`, with `CGO_ENABLED=0`. Building it also runs `go test` on every package. `just build` writes the same binary to `bin/app`.

## Consequences

- golangci-lint with every linter is strict. A new linter in a lock update can fail the gate on unchanged code, and the fix is a code change or a named exception.
- Replacing the `go` module of tabnix means a copy of its rules and a new path in `.config/golangci.yml`.
- A module dependency changes the vendor hash of the package. The same change updates `vendorHash` in `flake.nix`, and `nix build` prints the new value.

## Rules

- A linter is disabled by name with a reason in `.config/golangci.yml`. `(CI: lint-go)`
- `go.mod` and `flake.nix` name the same Go line. `(CI: lint-prose)`
- Every golangci-lint call passes `--config .config/golangci.yml`.
- No `if` statement has an init assignment, and no code compares errors with `==`, `!=`, or `switch`. `(CI: lint-go)`
- The artifact is the package of `flake.nix`, and its build runs the tests. `(CI: ci)`
